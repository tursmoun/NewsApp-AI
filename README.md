# Пульс · NewsApp

Локальное новостное приложение УУНиТ: React + TypeScript, Java **25** + Spring Boot 3.5.16 и PostgreSQL 17.6. Фото и видео хранятся на диске компьютера. Приложение никуда не опубликовано; внешняя почта и облачные хранилища не используются.

**Передача проекта и полная инструкция:** [HANDOFF.md](docs/HANDOFF.md). Там описаны установка с нуля, аккаунты и пароли, модерация, все возможности, Wi-Fi, проверка и ограничения. Исходники не содержат рабочую базу и пароли прежнего компьютера: они создаются заново у каждого разработчика.

**Перенос доработок 22.10.2026:** [UPDATE_NOTES.md](docs/UPDATE_NOTES.md) — новая CMS и остальные улучшения с сохранением модерации обычных пабликов их создателями.

**Последние согласованные изменения:** [SELECTED_CHANGES.md](docs/SELECTED_CHANGES.md) — отдельная проверка общей ленты после одобрения создателем паблика, простые рекомендации, русский поиск и системная/тёмная темы. **Цены хостинга и предложение автоматизации модерации:** [HOSTING_AND_MODERATION.md](docs/HOSTING_AND_MODERATION.md); эти сервисы пока не подключались.

**Управление сайтом без кода:** панель на React-admin по адресу `/cms` — новости, модерация, паблики, пользователи, жалобы и история. Войдите под администрацией или владельцем паблика и нажмите «Управление сайтом». [Инструкция CMS](docs/CMS.md).

**Предпроверка нейросетью:** [подключение Claude через MWAPI](docs/AI_PREREVIEW.md). После локального ввода ключа и включения в CMS нейросеть сортирует заявки по риску и соответствию новостному формату. Заголовок, текст и ссылка на источник передаются MWAPI; решения о публикации остаются за модератором. На новом компьютере ключ и подключение настраиваются отдельно.

**Для защиты кейса:** [сверка с презентацией и результаты проверок](docs/CASE_REVIEW.md), [сценарий живого показа на 5 минут](docs/DEMO.md).

## Запуск на этом компьютере

Дважды откройте `start.cmd` в Проводнике либо выполните в терминале IntelliJ из корня NewsApp:

```powershell
.\start.cmd
```

Откроется `http://localhost:5173/`. Лаунчер находит Java 25 (включая JBR в IntelliJ), запускает локальную PostgreSQL, при изменении исходников собирает backend и запускает frontend. Терминал оставьте открытым. `Ctrl+C` останавливает frontend/backend, запущенные этим окном. Команда `.\stop.cmd` останавливает их и PostgreSQL; данные сохраняются.

## Открыть с телефона в одной Wi-Fi-сети

Если приложение уже работает, выполните `stop.cmd`, затем запустите **`start-wifi.cmd`**. При первом запуске подтвердите системный запрос администратора Windows: он добавляет правило только для Node.js, TCP 5173, Wi-Fi-интерфейса и его локальной подсети. Backend и PostgreSQL остаются на loopback; настройки роутера не меняются.

Лаунчер напечатает `PHONE (same Wi-Fi): http://<IP ноутбука>:5173/` и сохранит адрес в `.local/wifi-url.txt`. Подключите телефон к той же Wi-Fi-сети и откройте этот адрес в браузере. На ноутбуке по-прежнему доступен `http://localhost:5173/`. Терминал должен работать, ноутбук не должен засыпать. VPN или изоляция клиентов в гостевой Wi-Fi-сети могут мешать соединению.

На телефоне доступны лента, вход, публикации и загрузка файлов. Тестовая почта доступна **только на ноутбуке через localhost**: новые аккаунты подтверждаются владельцем ноутбука через `/dev/mailbox`; исходящие письма не отправляются. Сессии на телефоне и ноутбуке отдельные. По локальному HTTP приложение работает как обычный сайт; установка PWA и некоторые возможности устройства требуют HTTPS.

После смены Wi-Fi или IP выполните `stop.cmd` → `start-wifi.cmd` и используйте новый адрес. Для возврата к доступу только с ноутбука: `stop.cmd` → `start.cmd`. Удалить добавленное правило можно в PowerShell администратора: `Remove-NetFirewallRule -Name NewsApp-WiFi-5173`.

## Аккаунты

Учётные данные заранее созданных аккаунтов находятся в **`.local/accounts.txt`**:

- `uunit.admin` — администрация платформы: личные новости, официальные паблики и любые публикации при необходимости.
- `club.owner` — создатель обычных пабликов «IT-сообщество» и «Спорт в кампусе»: проверяет их заявки и жалобы, одобряет и отклоняет новости.

Пароли случайные, создаются один раз при настройке. Не публикуйте содержимое `.local` и не переносите эти аккаунты в публичное приложение. Обычные пользователи создают свои аккаунты через регистрацию.

## Как проверить полный сценарий

1. Зарегистрироваться, открыть «Тестовая почта», перейти по ссылке и подтвердить адрес. Письма сохраняются локально в PostgreSQL, отправки наружу нет.
2. Войти и предложить личную новость через общую кнопку либо открыть нужный паблик и нажать «Предложить новость». В форме паблика получатель закреплён. Прикрепить фото или видео.
3. В другом браузере войти модератором: `uunit.admin` для личных/официальных новостей либо `club.owner` для его обычных пабликов. Откройте «Управление сайтом».
4. Одобрить или отклонить заявку с причиной. Автор увидит статус и уведомление.
5. Проверить общую ленту гостем. Отредактировать опубликованную новость: до одобрения правок гостю доступна прежняя версия.

Для всех действий нужны настоящие API и база. Подписки, сохранения, реакции, паблики, жалобы, профили и статусы сохраняются после перезапуска.

## Рабочие возможности

- Открытая общая лента, лента подписок, категории, поиск по новостям/названиям пабликов и подгрузка при прокрутке.
- Аккаунты, подтверждение почты, одноразовые ссылки сброса пароля и завершение прежних сессий после сброса.
- Паблики с владельцами. Новый паблик обычный; официальный статус и лимиты назначает только администрация.
- Предмодерация каждой новой публикации и ревизии, причины отклонения, уведомления и журнал решений.
- Четыре реакции: 👍 «Нравится», 🎉 «Поздравляю», 💡 «Интересно», ❤️ «Поддерживаю». Один аккаунт оставляет одну реакцию на новость, может заменить или снять её; прежние лайки сохраняются.
- До 4 фото по 10 МиБ (JPG/PNG/WebP), либо одно видео до 200 МиБ/3 минут/1080p (MP4/MOV). Сервер проверяет содержимое и преобразует видео в MP4 H.264/AAC, создаёт poster. Текст с видео необязателен. Заголовок 10–150, текст 50–10 000 символов, включая пробелы; сервер считает Unicode code points.
- Лимит 5 заявок на пользователя в сутки по Asia/Yekaterinburg, отдельные лимиты пабликов; для владельца паблика действует его повышенный лимит. Правки тоже расходуют квоту.
- Приватные медиа до одобрения, CSRF-защита, HttpOnly cookie, BCrypt, проверки ролей на сервере и ограничение частоты запросов.
- Адаптивный интерфейс, сохраняемая тема, PWA с экраном отсутствия связи, локальные шрифты и изображения.

## Платформы

Web на ПК и телефоне реализован. Исходники Android/iOS созданы через Capacitor в `android/` и `ios/`. Нативные сборки на устройствах **не проверены**: в этой среде нет Android SDK и macOS/Xcode. Для local-mode оболочка обращается к `localhost:5173`; Android использует `adb reverse`. Подробности — [MOBILE.md](docs/MOBILE.md).

## Установка на другом Windows-компьютере

Нужны JDK 25, Node.js 22.12+ (рекомендуется 24), pnpm 11.25.0 и встроенный Windows `tar.exe`. Для pnpm можно использовать `npm install --global pnpm@11.25.0`. Задайте JAVA_HOME, если JDK не находится автоматически.

```powershell
pnpm install --frozen-lockfile
.\start.cmd
```

При первом запуске инструменты скачиваются из Maven Central и сборки FFmpeg, указанной официальным сайтом FFmpeg. Сверяются контрольные суммы. PostgreSQL не устанавливается как системная служба. Все runtime-файлы и секреты находятся в `.local/`, исключённой из Git и доступа Vite.

## Разработка и проверки

```powershell
pnpm dev                    # только frontend, если backend/база уже работают
pnpm build                  # TypeScript + production сборка
pnpm format:check
pnpm test:network           # границы Wi-Fi и доверенные маркеры proxy
pnpm test:frontend          # текст, вложения и ошибки соединения
pnpm test:cms               # подключение панели управления
pnpm test:launcher          # загрузка инструментов и готовность frontend без сети
.\scripts\test-backend.ps1  # отдельная база newsapp_test
node scripts/smoke-local.mjs # сквозной HTTP-тест через Vite proxy, при запущенном приложении
pnpm mobile:sync             # сборка web + синхронизация исходников Capacitor
```

HTTP-тест создаёт локальный тестовый аккаунт и скрывает тестовую новость после проверки. Обычная база не очищается. Интеграционные тесты используют отдельную базу `newsapp_test`.

Frontend использует `/api`, Vite проксирует его на `127.0.0.1:8080`. PostgreSQL слушает `127.0.0.1:55432`. Spring тоже доступен только через loopback. В `.env.example` только публичный путь API. Секреты в `VITE_*` помещать нельзя.

### Отдельный запуск Spring / IntelliJ

Откройте `backend/pom.xml` как Maven-проект, укажите JDK 25. Главный класс — `ru.uunit.news.NewsApplication`. Для запуска из терминала с локальными настройками:

```powershell
. .\scripts\local-env.ps1
.\scripts\start-database.ps1
& $maven -f backend/pom.xml "-Dmaven.repo.local=$localRoot\m2" spring-boot:run
```

Для Run Configuration IntelliJ перенесите значения окружения из `.local/config.json`: NEWSAPP_DB_PASSWORD, NEWSAPP_ADMIN_PASSWORD, NEWSAPP_OWNER_PASSWORD; NEWSAPP_LOCAL_DIR укажите абсолютным путём `.local`; NEWSAPP_FFMPEG/NEWSAPP_FFPROBE — абсолютные пути к `.local/tools/ffmpeg/bin/*.exe`. Рабочая директория — корень NewsApp. Ничего из этого не добавляйте в общую конфигурацию с секретами.

## Данные, журналы и резервная копия

- `.local/postgres-data/` — постоянная PostgreSQL-база.
- `.local/media/` — загруженные фото, видео и обложки; версии сохраняют свои вложения для истории.
- `.local/config.json`, `.local/accounts.txt` — локальные секреты.
- `.local/logs/` — журналы backend/frontend/PostgreSQL и тестов.

Для согласованной физической резервной копии сначала `.\stop.cmd`, затем `.\scripts\backup-local.ps1`. ZIP сохраняется в `.local/backups/`, включает базу, медиа и локальные настройки. Для восстановления нужен тот же PostgreSQL 17, закрытые процессы и новая пустая локальная папка. Не распаковывайте поверх работающей базы. Копия содержит пароли локальных аккаунтов, её следует хранить приватно.
